# 텍스트 이력서 작성 가이드

교재: 「이 교재를 쓰는 법」 1번 사전 과제 (3쪽) · 1.3절 나 자신에 대한 이해 (11~12쪽) · 쓰는 날: 수업 전(사전 과제), Day 1 오전 · 쓰는 곳: 작업 폴더의 `resume.md`, 워크시트 「자기 이해 노트」

## 이 가이드에서 볼 것

텍스트 이력서는 사흘 동안 쓰는 재료입니다. 슬로건 · 근거자료 · CTA가 모두 이 한 파일에서 나옵니다. 이 가이드는 두 부분입니다.

- **수업 전:** 빈 양식을 받아 `resume.md`로 저장하고, 열 칸을 채우는 요령
- **Day 1 1.3절:** Claude Code가 이력서를 읽고 질문하게 해 자기 이해 노트를 만드는 순서

장점을 찾는 세 가지 표시(장점 · 반복되는 관심 · 앞으로의 목표)와 여섯 질문은 교재 1.3절에 있습니다. 여기서는 되풀이하지 않고 손으로 하는 순서를 적습니다.

## 1. 양식과 작성 예 받기

| 파일 | 무엇 |
|---|---|
| [텍스트 이력서 양식](https://github.com/wild-mental/ax-wave-personal-brand-wildmental/blob/main/worksheet-template/text-resume-template.md) | 열 칸이 비어 있는 양식. 내가 채울 파일 |
| [백유림 텍스트 이력서](https://github.com/wild-mental/ax-wave-personal-brand-wildmental/blob/main/worksheet-template/baek-yurim-resume.md) | 같은 양식을 중심 예제 백유림이 채운 작성 예. 백유림은 수업을 위해 만든 **가상 인물**이고, 경력 · 수치는 모두 지어낸 것입니다 |

1. 바탕화면이나 문서 폴더에 `personal-brand-site` 폴더를 만듭니다(사전 안내 5번). 첫날 이 폴더를 작업 폴더로 그대로 씁니다.
2. 위 표의 **텍스트 이력서 양식**을 누릅니다. GitHub 화면에서 파일이 열립니다.
3. 파일 위쪽 막대 오른쪽의 **Download raw file**(아래 화살표 모양의 내려받기 아이콘)을 누릅니다.
4. **다운로드** 폴더에 `text-resume-template.md`가 생깁니다. 이 파일을 `personal-brand-site` 폴더로 옮기고, 이름을 `resume.md`로 바꿉니다.
5. 이름이 정확히 `resume.md`인지 봅니다. Windows에서는 먼저 파일 확장자가 보이게 켜 둡니다(「[Windows 사용자 메모](../help/windows-notes.md)」).

**열고 고치기.** Mac은 파일을 오른쪽 클릭 → **다음으로 열기 → 텍스트 편집기**, Windows는 오른쪽 클릭 → **연결 프로그램 → 메모장**으로 엽니다. 다 쓰면 `Cmd+S`(Windows `Ctrl+S`)로 저장합니다. 메모장에서 다른 이름으로 저장할 때는 파일 형식을 **모든 파일**, 인코딩을 **UTF-8**로 두고 이름 끝에 `.txt`가 붙지 않게 합니다.

워드나 한글 프로그램으로 쓰고 싶다면 거기서 쓴 뒤 글만 복사해 `resume.md`의 칸에 붙여 넣습니다. 지시문은 `.md` 파일만 읽습니다.

## 2. 열 칸 채우는 요령

양식의 칸 순서대로 씁니다. 워드 2쪽 안팎이면 충분합니다. 시간이 모자라면 **1 · 2 · 3 · 7번**을 먼저 채웁니다(Day 1에 이 넷이 가장 먼저 쓰입니다).

| 칸 | 이렇게 씁니다 | 사흘 동안 쓰이는 곳 |
|---|---|---|
| 1. 기본 정보 | 직함은 지금 하는 일, 또는 되고 싶은 일을 지금 하는 일처럼 씁니다. 공개 연락 채널에는 사이트에 공개해도 되는 것만 적습니다 | 첫 화면 이름 · 직함 (2.2), CTA 창구 (3.2) |
| 2. 지금 하는 일 | 무슨 일을, 누구를 위해, 왜 하는지 2~4문장 | 상품으로서의 나 (1.4) |
| 3. 지향점 | 사이트를 본 사람과 함께 해 보고 싶은 일 2~4가지 | 지향점 슬로건 (1.5), CTA 분야 (3.2) |
| 4. 성격과 일하는 방식 | 나를 설명하는 말 하나에 실제 일화 한 줄씩 | 성격 슬로건 (1.5) |
| 5. 핵심 능력 | 능력 하나에 어디서 써 봤는지 한 줄씩 | 능력 슬로건 (1.5) |
| 6. 경력 | 기간 · 소속과 역할 · 한 일. 아르바이트 · 인턴 · 동아리 운영도 됩니다 | 걸어온 길 섹션 (1.8) |
| 7. 대표 프로젝트 | 1~2개. 풀고 싶은 문제 · 내가 한 일 · 근거자료 · 보여 줄 인상 | 이력 슬로건 (1.5), 근거자료 (1.6), 이미지 (2.4) |
| 8. 학력 · 교육 | 이 과정을 포함해 적습니다 | 걸어온 길 섹션 |
| 9. 발표 · 글 · 수상 · 기록 | 없으면 공부 기록, 블로그 글, 취미 기록도 좋습니다 | 근거자료 후보 (1.6), 글감 (3.5) |
| 10. 공개 범위 메모 | 사이트에 공개할 것 / 공개하지 않을 것 | 공개 전 확인 (3.3) |

### 칸마다 한 가지만 기억하기

- **일화가 형용사를 이깁니다.** "성실함"보다 "2년 동안 동아리 회계 장부를 한 번도 빠짐없이 마감했다"가 슬로건과 근거자료의 재료가 됩니다.
- **숫자에는 언제 · 어디서 · 무엇 중의를 붙입니다.** "많은 사람이 참여"보다 "2025년 가을, 학과 행사 참가자 80명 중 62명이 설문에 답함". 1.6절의 숫자 카드가 이 한 줄에서 나옵니다.
- **7번의 근거자료는 지금 보여 줄 수 있는 것만 적습니다.** 배포된 웹사이트 주소, 결과 문서, 사진, 함께 일한 사람의 말. 없으면 비워 두고 1.6절에서 재구성 자료를 생각합니다.
- **7번의 '보여 줄 인상'은 한 장면으로 씁니다.** "카페 창가에서 노트북으로 손님 설문 결과를 정리하는 장면 — 꼼꼼함"처럼. 2.4절에서 이 장면이 사진이나 생성 이미지가 됩니다.
- **10번을 먼저 정해도 좋습니다.** 공개하지 않을 것을 미리 적어 두면 Claude Code가 그것을 사이트에 넣었을 때 바로 알아챕니다.

백유림 작성 예는 칸을 어떻게 채우는지 보여 주는 본보기이지 정답이 아닙니다. 백유림의 문장을 바꿔 쓰지 말고 내 경험으로 씁니다.

## 3. Day 1: 이력서로 자기 이해 노트 만들기 (1.3)

1. 이력서를 처음부터 다시 읽으며 교재 1.3절의 세 가지(장점 · 반복되는 관심 · 앞으로의 목표)를 표시합니다. 텍스트 편집기 · 메모장에서 그 줄 끝에 `[장점]`, `[관심]`, `[목표]`처럼 적어도 됩니다.
2. Claude Code 입력창 아래 폴더 선택이 `personal-brand-site`인지 봅니다.
3. 지시문 킷의 「[자기 이해 질문 지시문](../kits/claude-code-prompts.md)」을 복사해 보냅니다.
4. 질문이 하나씩 옵니다. 한 질문에 하나씩 답합니다. 답은 두세 문장으로, 가능하면 실제 일화를 넣습니다.
5. 여섯 개에 다 답하면 표 초안이 나옵니다.

**이렇게 나오면 정상입니다.**

- 질문이 한 번에 하나씩, 모두 여섯 개 옵니다. 질문에 내 이력서의 경력이나 프로젝트 이름이 들어 있습니다.
- 초안 표의 모든 줄이 내가 한 답에서 나왔습니다. 답하지 않은 칸에는 "답 없음"이 있습니다.
- `worksheet.md`는 바뀌지 않았고, 초안은 대화창에만 있습니다.

6. 초안을 읽고 내 말로 다듬어 `worksheet.md`의 「자기 이해 노트」 표에 직접 옮겨 씁니다. 표 칸 안에는 `|` 기호와 줄 바꿈을 쓰지 않습니다.
7. 「자기 이해 노트」 끝의 **완료 기준 체크리스트**를 확인하고 `- [ ]`를 `- [x]`로 바꿉니다.

### 다시 지시하는 말

| 이렇게 나왔다 | 다시 지시하는 말 |
|---|---|
| 질문 여섯 개가 한꺼번에 왔다 | 질문은 한 번에 하나씩만 해 줘. 첫 번째 질문부터 다시 해 줘. |
| 내가 하지 않은 말이 초안에 있다 | 초안의 줄마다 내 답의 어느 문장에서 나왔는지 표시해 줘. 내 답에 없는 내용은 지워 줘. |
| 장점이 "성실함"처럼 말만 있고 일화가 없다 | 장점 〈번호〉에 맞는 일화를 묻는 질문을 하나 더 해 줘. |
| `worksheet.md`를 고치려 한다 | 허락하지 않고 "worksheet.md는 고치지 말고 대화창에만 보여 줘."라고 보냅니다. |

## 자주 하는 실수와 고친 예

- **업무 목록만 썼다** — 카페 아르바이트를 "주문 받기, 음료 제조, 마감 청소"로만 적었습니다. → 그 일에서 내가 남다르게 한 것을 한 줄 더합니다. "주말 마감 체크리스트를 만들어 마감 시간을 40분에서 25분으로 줄임(2025년 여름, 매장 기록)."
- **목표를 "성장하고 싶다"로 썼다** — 3번 지향점이 누구와 무엇을 할지 보이지 않습니다. → "동네 가게 사장님들의 온라인 홍보를 돕는 일을 프로젝트로 맡아 보고 싶다"처럼 함께할 사람과 일을 넣습니다.
- **공개하면 안 되는 것을 그대로 적었다** — 개인 휴대폰 번호, 전 직장의 내부 매출, 친구 이름이 들어 있었습니다. → 10번 「공개 범위 메모」의 비공개에 적고, 본문에서는 "고객사 매출 15% 증가(내부 자료로 확인)"처럼 공개해도 되는 수준으로 바꿉니다.
- **백유림 이력서를 고쳐 쓰기 시작했다** — 문장이 그럴듯해지지만 내 일화가 사라집니다. → 빈 양식에서 다시 시작하고, 작성 예는 칸의 길이와 말투만 참고합니다.

## 제대로 됐는지 확인

- [ ] 작업 폴더 `personal-brand-site`에 `resume.md`가 있고, 텍스트 편집기 · 메모장으로 열린다
- [ ] 1 · 2 · 3 · 7번이 채워져 있다 (나머지 칸은 Day 1 중에 채워도 됩니다)
- [ ] 4번 성격의 말마다 실제 일화가 한 줄씩 있다
- [ ] 숫자마다 언제 · 어디서 · 무엇 중의 숫자인지 적었다
- [ ] 10번 「공개 범위 메모」에 공개 / 비공개를 적었다
- [ ] (Day 1) 「자기 이해 노트」의 장점 세 개가 일화와 묶였고, 앞으로의 목표를 한 문장으로 썼다

## 막혔을 때

- **쓸 경력이 없다고 느껴집니다.** 수업 결과물(앞 과목의 개념 프로토타입이나 사이트 시안), 공부 기록, 동아리 · 봉사 · 취미로 끝까지 해낸 일을 7번 대표 프로젝트로 씁니다(교재 1.3절). 앞 과목에서 만든 결과물은 그대로 대표 프로젝트가 됩니다.
- **양식 파일을 받았더니 이름이 `text-resume-template (1).md`입니다.** 같은 파일을 여러 번 받은 것입니다. 하나만 남기고 이름을 `resume.md`로 바꿉니다.
- **`.md` 파일이 텍스트 편집기가 아닌 다른 앱으로 열립니다.** 오른쪽 클릭 → 다음으로 열기(Windows는 연결 프로그램)에서 텍스트 편집기 · 메모장을 고릅니다.
- **Claude Code가 이력서를 찾지 못합니다.** 폴더 선택이 `personal-brand-site`인지, 파일 이름이 `resume.md`(끝에 `.txt` 없음)인지 봅니다. 「[작업 폴더와 비공개 저장소 준비 가이드](workspace-repo-setup-guide.md)」 4번을 봅니다.
- **이력서를 못 써 온 채 수업에 왔습니다.** Day 1 오전에 1 · 2 · 3 · 7번만 먼저 채우고 1.3절을 따라갑니다. 나머지 칸은 오후 실습 사이사이에 채웁니다.
