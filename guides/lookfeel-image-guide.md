# 룩앤필과 이미지 가이드

교재: 2.3절 룩앤필 설정 (30~33쪽) · 2.4절 이미지 만들기 (33~35쪽) · 부록 A-5 생성 이미지 만들기와 표기 (52쪽) · 쓰는 날: Day 2 오전~오후 · 쓰는 곳: 워크시트 「룩앤필 설정」 · 「미디어 제작 목록」, 작업 폴더의 `DESIGN.md` · `images/` · `index.html`

## 이 가이드에서 볼 것

3단계 시각화 강화의 앞 두 걸음입니다. 사이트 전체의 인상(룩앤필)을 정해 `DESIGN.md`에 규칙으로 덧붙이고, 그 인상을 만드는 이미지를 모으거나 만들어 넣은 뒤, 근거자료를 정한 형태의 블록으로 화면에 놓습니다. 다섯 가지 룩앤필 유형, 이미지의 세 가지 출처, 장면을 설명하는 다섯 가지는 교재 2.3 · 2.4절에 있습니다. 이 가이드는 손으로 하는 순서와 "이렇게 나오면 정상"인 모습, 다시 지시하는 말을 채웁니다.

| 순서 | 하는 일 | 지시문 |
|---|---|---|
| 1 | 룩앤필 유형 고르기, 인상 키워드 세 개 | — (내가 함) |
| 2 | 키워드를 색 · 사진 · 글자 · 움직임 규칙으로 | — (내가 함) |
| 3 | DESIGN.md에 덧붙이고 사이트에 입히기 | 「룩앤필 지시문」 |
| 4 | 미디어 제작 목록 만들기 | — (내가 함) |
| 5 | 본인 사진 · 화면 캡처 모으기 | — (내가 함) |
| 6 | 생성 이미지 만들기 | 이미지 생성 AI |
| 7 | 사이트에 이미지 넣기 | 「이미지 넣기 지시문」 |
| 8 | 근거자료 블록 만들기 | 「근거자료 블록 지시문」 |

## 1. 룩앤필 유형 고르기

1. 「순서와 시각화 전략표」의 「인상」 칸을 위에서 아래로 읽고, 가장 자주 나오는 낱말 두세 개에 표시합니다.
2. 교재 2.3절 표의 「어울리는 사람」 열을 보며 아래 질문에 답해 봅니다.

| 질문 | "예"라면 |
|---|---|
| 내 활동과 현장이 움직이는 장면으로 보여 줄 때 가장 잘 전해지는가? | 영상형 |
| 결과물이 눈에 보이는 일(디자인 · 사진 · 화면 · 작품)인가? | 갤러리형 |
| 걸어온 길과 생각을 차례로 들려주고 싶은가? | 이야기형 |
| 청자가 관심 분야를 직접 골라 보게 하고 싶은가? | 인터랙션형 |
| 첫인상은 강하게, 아래는 다른 방식으로 이어 가고 싶은가? | 혼합형 (섹션마다 어느 유형인지 정합니다) |

3. 참고 장면을 직접 열어 봅니다. 컴퓨터 브라우저를 넓게 펴고 천천히 스크롤합니다. 페이지는 그 뒤 바뀔 수 있습니다.

| 유형 | 열어 볼 곳 | 볼 것 |
|---|---|---|
| 영상형 · 이야기형 | [Apple MacBook Pro 상품 소개 페이지](https://www.apple.com/kr/macbook-pro/proled-xdr-display/) | 어두운 배경에서 영상으로 여는 첫 화면, 큰 문장이 장면을 이끄는 섹션 |
| 갤러리형 · 인터랙션형 | [Apple Mac Studio 상품 소개 페이지](https://www.apple.com/kr/mac-studio/) | 밝은 바탕에 사진 하나와 짧은 문장만 둔 장면, 질문에서 선택지로 넘어가는 순서 |
| 갤러리형 (개인 사이트) | [PBJ Working](https://www.pbjworking.com/) | 어두운 배경 위에 프로젝트마다 큰 사진과 굵은 제목을 놓은 '주요 프로젝트' 영역 |

4. 유형 하나를 고르고, 인상을 낱말 세 개로 줄입니다. 1번에서 표시한 낱말이 출발점입니다.

## 2. 인상 키워드를 디자인 규칙으로 바꾸기

「룩앤필 설정」 표의 색 · 사진 · 글자 · 움직임 칸은 Claude Code가 그대로 따를 수 있을 만큼 구체적으로 씁니다. 인상 낱말 하나가 규칙 하나 이상으로 바뀌어야 합니다.

| 칸 | 흐린 예 → 구체적인 예 (인상: 차분함 · 정확함 · 신뢰) |
|---|---|
| 색 | 차분한 색 → 배경 밝은 회백색, 글자 짙은 남색, 강조색은 청록 하나만(버튼과 숫자에만) |
| 사진 | 깔끔한 사진 → 사진은 모두 같은 비율(4:3), 사진 위에 글자를 얹지 않음, 흑백 사진은 쓰지 않음 |
| 글자 | 읽기 쉽게 → 슬로건은 크고 굵게 두 줄 이내, 설명은 한 단계 작게, 한 줄 길이는 화면 가운데 3분의 2 안 |
| 움직임 | 은은하게 → 카드는 아래에서 위로 짧게 나타남, 첫 화면 장면 전환은 5초 간격, 깜빡이는 효과는 쓰지 않음 |

- 색은 이름("짙은 남색")으로 써도 됩니다. 색 번호(`#1f3b5c` 같은 값)를 알면 함께 적습니다. `DESIGN.md`에 이미 정한 색이 있으면 그 색을 씁니다.
- 앞 과목의 `DESIGN.md` 규칙과 부딪치면 이 사이트의 규칙이 이깁니다. 다만 앞의 내용은 지우지 않고 덧붙입니다(교재 2.3절).

## 3. DESIGN.md에 덧붙이고 사이트에 입히기

1. 「룩앤필 설정」을 채우고 저장합니다.
2. 지시문 킷의 「[룩앤필 지시문](../kits/claude-code-prompts.md)」을 복사합니다. 지시문 안의 `<유형>`을 내가 고른 유형 이름(예: 이야기형)으로 바꾸고 보냅니다.

**이렇게 나오면 정상입니다.**

- 작업 폴더에 `index-before-lookfeel.html`(룩앤필 전 복사본)이 생겼습니다.
- `DESIGN.md` 맨 끝에 `## 개인 브랜드 사이트 규칙 (룩앤필: 〈유형〉)` 제목과 그 아래 규칙이 생겼고, 앞의 내용은 그대로입니다.
- 브라우저를 새로 고치면 모든 섹션의 색 · 글자 · 여백이 같은 인상으로 바뀌었고, 섹션 순서와 문장은 그대로입니다.
- Claude Code가 바꾼 규칙을 목록으로 알려 줍니다.

`DESIGN.md`가 제대로 덧붙여졌는지는 이렇게 확인합니다.

```text
@DESIGN.md 에서 이번에 덧붙인 부분만 그대로 보여 줘. 앞의 내용이 지워지거나 바뀐 곳이 있으면 알려 줘. 파일은 고치지 마.
```

마음에 들지 않는 곳은 한 번에 한 가지씩 고칩니다(「[Claude Code 사이트 제작 가이드](claude-code-site-guide.md)」 5번). 전체가 마음에 들지 않으면 `index-before-lookfeel.html`로 되돌리고 「룩앤필 설정」의 규칙을 고친 뒤 다시 보냅니다.

## 4. 미디어 제작 목록 만들기

1. 「순서와 시각화 전략표」를 위에서 아래로 읽으며 사진 · 이미지 · 영상이 필요한 자리를 모두 「미디어 제작 목록」에 한 줄씩 적습니다. 뼈대 페이지의 회색 상자 하나가 한 줄입니다.
2. 자리마다 출처를 정합니다. 본인 사진 → 화면 캡처 → 생성 이미지 순서로 생각합니다(교재 2.4절).
3. 파일 이름을 미리 정해 적습니다. 영문 소문자와 숫자, 하이픈(`-`)만 쓰고 띄어쓰기와 한글은 쓰지 않습니다. 예) `profile.jpg`, `project1-screen.png`, `hero-1.jpg`
4. 출처가 생성 이미지인 줄에는 다섯 가지 설명을 적습니다(6번).

미디어 재생(움직임 ①)에 쓸 사진 2~3장이나 짧은 영상도 이 목록에 넣습니다. 영상 만드는 법은 「[움직임 넣기 가이드](motion-guide.md)」 1번을 봅니다.

## 5. 본인 사진과 화면 캡처 모으기

### 휴대폰 사진을 컴퓨터로 옮기기

| | 이렇게 합니다 |
|---|---|
| iPhone → Mac | 사진 앱에서 공유 → AirDrop으로 내 Mac에 보냅니다 |
| 휴대폰 → Windows · 그 밖 | 휴대폰을 USB 케이블로 연결해 사진 폴더에서 복사하거나, 나에게 보내는 이메일 · 클라우드 드라이브에 원본으로 올린 뒤 컴퓨터에서 내려받습니다 |

메신저로 보내면 사진이 작게 줄어들 수 있습니다. 첫 화면처럼 크게 쓸 사진은 원본으로 옮깁니다.

**iPhone 사진의 확장자가 `.heic`이면** 브라우저에서 보이지 않을 수 있습니다. Mac은 사진을 미리보기로 열고 **파일 → 내보내기**에서 형식을 JPEG로 바꿔 저장합니다. 앞으로 찍을 사진은 iPhone **설정 → 카메라 → 포맷 → 높은 호환성**으로 바꾸면 JPG로 찍힙니다.

### 화면 캡처하기

| | Mac | Windows |
|---|---|---|
| 영역을 골라 캡처 | `Cmd+Shift+4` 후 끌어서 영역 선택. 바탕화면에 파일로 저장됩니다 | `Win+Shift+S` 후 영역 선택. 오른쪽 아래 알림을 눌러 캡처 도구에서 저장합니다 |

캡처 전에 개인 이메일 · 실명 · 알림 · 회사 내부 정보가 보이지 않게 창을 정리하거나, 캡처한 뒤 그 부분을 잘라냅니다. 자르기는 Mac 미리보기(**도구 → 자르기**), Windows 사진 앱(**편집 → 자르기**)에서 합니다.

### 크기 줄이고 images 폴더에 넣기

휴대폰 사진은 한 장에 3~5MB가 넘기도 합니다. 그대로 넣으면 휴대폰에서 사이트가 느리게 열립니다. 긴 쪽을 2000px 안팎으로 줄여 씁니다.

- Mac: 미리보기로 열고 **도구 → 크기 조절**에서 폭을 2000 이하로 바꾼 뒤 저장
- Windows: 사진 앱에서 **⋯ → 이미지 크기 조정**, 또는 그림판의 **크기 조정**

줄인 파일은 4번에서 정한 이름으로 바꿔 작업 폴더의 `images/`에 넣습니다.

## 6. 생성 이미지 만들기 (부록 A-5)

1. 이미지 생성 AI(예: ChatGPT의 이미지 생성)를 엽니다. 계정은 사전 안내에서 준비했습니다.
2. 「미디어 제작 목록」에 적은 다섯 가지(장면 · 인물과 사물 · 시간과 빛 · 분위기 · 넣지 않을 것)를 한 덩어리로 붙여 보냅니다. 설명은 한국어로 써도 됩니다. 끝에 비율을 한 줄 더합니다. 예) "가로로 긴 16:9 비율로", "4:3 비율로"
3. 결과가 다르면 한 가지씩 고쳐 달라고 합니다. 예) "같은 장면에서 빛만 더 따뜻한 오후 햇빛으로 바꿔 줘", "화면 속 글자를 모두 없애 줘."
4. 마음에 드는 이미지를 내려받아 4번에서 정한 영어 파일 이름으로 작업 폴더의 `images/`에 넣습니다.

예시 설명입니다(중심 예제 밖의 예). 글자를 그대로 쓰지 말고 내 장면으로 씁니다.

```text
장면: 동네 작은 빵집 계산대 옆, 노트북으로 손님 설문 결과를 정리하는 모습
인물 · 사물: 뒷모습의 한 사람, 노트북 화면의 막대그래프, 계산대 위 빵 바구니
시간과 빛: 늦은 오후, 창으로 들어오는 따뜻한 햇빛
분위기: 꼼꼼함, 동네 가게에 대한 애정
넣지 않을 것: 얼굴, 읽을 수 있는 글자 · 숫자, 실제 가게 이름과 로고
가로로 긴 16:9 비율로 만들어 줘.
```

**만들지 않는 것.** 실존 인물과 닮은 얼굴, 다른 회사의 로고, 실제로 없었던 일을 사실처럼 보이게 하는 장면(예: 가 본 적 없는 행사에서 연단에 선 내 모습)은 만들지 않습니다. 근거자료를 재구성할 때는 실제 있었던 활동만 다시 그립니다(교재 1.6절).

## 7. 사이트에 이미지 넣기

1. `images/` 안의 파일 이름이 「미디어 제작 목록」에 적은 이름과 같은지 봅니다.
2. 지시문 킷의 「[이미지 넣기 지시문](../kits/claude-code-prompts.md)」을 복사해 보냅니다.

**이렇게 나오면 정상입니다.**

- 회색 상자가 있던 자리에 목록의 사진이 들어갔습니다. 파일이 없는 자리는 회색 상자 그대로이고, Claude Code가 어느 자리인지 알려 줍니다.
- 출처가 생성 이미지인 사진 옆(또는 아래)에 작게 '생성 이미지'라고 적혀 있습니다.
- 휴대폰 화면 보기에서 사진이 화면 밖으로 넘치거나 중요한 부분이 잘리지 않습니다.
- 대체 텍스트(alt)는 화면에 보이지 않습니다. 확인하려면 "index.html 의 사진마다 대체 텍스트를 목록으로 보여 줘. 파일은 고치지 마."라고 묻습니다. 사진마다 무엇이 보이는지 한 문장씩 있으면 됩니다.

## 8. 근거자료 블록 만들기

이미지를 넣은 뒤, 1.6절의 「근거자료 연결표」에서 정한 형태대로 근거자료를 화면에 놓습니다(교재 2.4절).

1. 「근거자료 연결표」의 「형태」 칸이 다섯 가지 이름(숫자 카드 · 수치 그래프 · 인물 증언 · 화면 캡처 · 현장 실사) 가운데 하나로 적혀 있는지 봅니다.
2. 화면 캡처 · 현장 실사로 정한 근거는 그 파일이 `images/`에 있는지 봅니다.
3. 지시문 킷의 「[근거자료 블록 지시문](../kits/claude-code-prompts.md)」을 복사해 보냅니다.

**이렇게 나오면 정상입니다.**

| 형태 | 화면에서 |
|---|---|
| 숫자 카드 | 큰 숫자 하나와 그 아래 한 줄 설명(언제 · 어디서 · 무엇 중의 숫자인지) |
| 수치 그래프 | 기간에 따른 막대나 선. 숫자는 연결표에 적힌 것뿐 |
| 인물 증언 | 핵심 한 문장과 말한 사람(공개 허락 받은 이름이나 역할) |
| 화면 캡처 · 현장 실사 | `images/`의 그 파일과 한 줄 설명 |

- 블록이 연결표의 슬로건이 있는 섹션에 들어갔습니다. Claude Code가 만든 블록을 섹션별로 알려 줍니다.
- 연결표에 "(가상)", "예시", "재구성(생성 이미지)"처럼 적은 표기가 블록에도 그대로 붙어 있습니다.
- 다른 곳은 바뀌지 않았습니다.

블록이 연결표에 없는 숫자를 보여 주면 바로 지웁니다(아래 표). 숫자 카드와 그래프가 한 섹션에 너무 많으면 그 섹션은 「[움직임 넣기 가이드](motion-guide.md)」의 스크롤 진입 전환으로 하나씩 나타나게 하면 읽기 쉬워집니다.

## 다시 지시하는 말

| 이렇게 나왔다 | 다시 지시하는 말 |
|---|---|
| 룩앤필을 입히며 문장이 바뀌었다 | 섹션의 문장을 @index-before-lookfeel.html 과 똑같이 되돌려 줘. 색 · 글자 · 여백은 지금대로 둬. |
| DESIGN.md의 앞 내용이 지워졌다 | DESIGN.md 의 앞 내용이 지워졌어. 지운 내용을 되살리고, 이번 규칙은 맨 끝에만 덧붙여 줘. |
| 섹션마다 인상이 달라 보인다 | 〈섹션 이름〉 섹션이 다른 섹션과 달라 보여. @DESIGN.md 의 '개인 브랜드 사이트 규칙'과 다른 곳만 목록으로 보여 주고, 그 부분만 규칙대로 고쳐 줘. |
| 사진이 휴대폰에서 잘린다 | 휴대폰 화면에서 〈파일 이름〉 사진의 〈무엇〉이 잘려. 그 사진은 잘리지 않고 다 보이게 해 줘. 다른 사진은 그대로 둬. |
| 생성 이미지 표기가 빠졌다 | @worksheet.md 의 「미디어 제작 목록」에서 출처가 '생성 이미지'인 파일을 모두 찾아, 사이트에 '생성 이미지' 표기가 붙었는지 표로 보여 주고 빠진 곳에 붙여 줘. |

| 그래프 숫자가 이상하다 | 〈섹션〉의 수치 그래프에 쓴 숫자를 표로 보여 줘. 연결표의 숫자와 다르면 연결표대로 고쳐 줘. |

## 자주 하는 실수와 고친 예

- **유형을 정하지 않고 색만 바꿨다** — 섹션마다 다른 참고 사이트를 따라 해, 위는 영상형 · 아래는 갤러리형 · 중간은 이야기형이 섞였습니다. → 혼합형이라면 「룩앤필 설정」에 섹션별 유형을 적고, 그렇지 않으면 하나로 맞춥니다.
- **파일 이름을 한글 · 띄어쓰기로 저장했다** — `내 사진 최종.jpg`가 일부 환경에서 보이지 않았습니다. → `profile.jpg`처럼 영문 소문자와 하이픈으로 바꾸고, 「미디어 제작 목록」의 이름도 함께 고칩니다.
- **단체 사진을 허락 없이 넣었다** → 함께 나온 사람에게 허락을 받거나, 그 사람이 보이지 않게 자르거나, 생성 이미지로 재구성하고 표기합니다.
- **생성 이미지 속에 이상한 글자가 생겼다** — 간판과 화면에 읽을 수 없는 글자가 가득했습니다. → 「넣지 않을 것」에 "읽을 수 있는 글자 · 숫자"를 넣고 다시 만들게 합니다.
- **근거자료 블록을 먼저 만들고 연결표를 나중에 고쳤다** — 사이트와 워크시트가 어긋났습니다. → 연결표를 먼저 고치고, 지시문을 다시 보내 블록을 맞춥니다. 기준은 언제나 워크시트입니다.

## 완료 기준 체크리스트 확인 방법

- **룩앤필 설정:** 「유형」 칸에 다섯 이름 가운데 하나가 있는지, 「인상 키워드」가 세 개인지, 3번의 `DESIGN.md` 확인 말로 덧붙인 규칙을 봤는지, 브라우저에서 위에서 아래로 스크롤하며 튀는 섹션이 없는지 봅니다.
- **미디어 제작 목록:** 줄마다 「출처」가 세 가지 가운데 하나인지, 생성 이미지 줄의 사진에 표기가 보이는지, 다른 사람이 나오는 사진에 허락을 받았는지, 「근거자료 연결표」의 근거가 8번 표의 모습으로 화면에 들어갔는지 봅니다.

## 막혔을 때

- **유형을 하나로 못 고르겠습니다.** 첫 화면 하나만 먼저 정합니다. 첫 화면에서 청자가 받을 인상이 가장 중요합니다. 아래 섹션은 이야기형으로 이어 가는 혼합형이 무난합니다.
- **사진이 사이트에 안 보입니다.** 파일이 `images/` 안에 있는지, 이름이 목록과 글자 하나까지 같은지(대소문자, `.jpg`와 `.jpeg`), 확장자가 `.heic`가 아닌지 봅니다. 그래도 안 보이면 "〈파일 이름〉이 사이트에 안 보여. 원인을 찾아 그 부분만 고쳐 줘."라고 보냅니다.
- **이미지 생성 AI가 요청을 거절합니다.** 실존 인물 · 상표가 들어간 설명일 때가 많습니다. 그 부분을 빼고 다시 씁니다.
- **이미지 생성 AI를 쓸 수 없습니다.** 본인 사진과 화면 캡처만으로도 충분합니다. 기록이 없는 장면은 그 자리를 줄이거나, 근거자료를 숫자 카드 · 인물 증언처럼 이미지가 필요 없는 형태로 바꿉니다.
- **근거자료 블록 지시문이 연결표를 찾지 못합니다.** 워크시트의 `###` 제목 「근거자료 연결표」를 지우거나 바꾸지 않았는지, 저장했는지 봅니다.
