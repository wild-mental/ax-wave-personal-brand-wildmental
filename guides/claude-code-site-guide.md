# Claude Code 사이트 제작 가이드

교재: 2.2절 첫 화면 만들기와 한 가지씩 고치기 (29쪽) · 부록 A-2 Claude Code로 사이트를 만들 때 지킬 것 (51쪽) · 쓰는 날: Day 2 오전, 그리고 사이트를 고칠 때마다 · 쓰는 곳: Claude Code 데스크톱 앱의 Code 탭, 작업 폴더의 `index.html`, 워크시트 「사이트 첫 화면」

## 이 가이드에서 볼 것

Claude Code로 사이트를 만드는 일은 **요구사항 → 지시 → 브라우저 확인 → 수정**의 되풀이입니다(교재 2.2절). 이 가이드는 그 한 바퀴를 화면 순서대로 따라갑니다. 2.2절의 「첫 화면 지시문」으로 설명하지만, Day 2 · Day 3의 모든 사이트 지시문(룩앤필 · 이미지 넣기 · 근거자료 블록 · 세 가지 움직임 · CTA)이 같은 순서입니다.

- 지킬 것 여섯 가지는 교재 부록 A-2의 표에 있고, 지시문 전문은 [지시문 킷](../kits/claude-code-prompts.md)에 있습니다. 여기서는 되풀이하지 않고 손으로 하는 순서와 다시 지시하는 말을 적습니다.
- 앱 로그인과 작업 폴더 열기는 「[작업 폴더와 비공개 저장소 준비 가이드](workspace-repo-setup-guide.md)」 4번을 봅니다.

| 단계 | 하는 일 | 이 가이드 |
|---|---|---|
| 요구사항 | 무엇을 바라는지 워크시트에서 확인합니다 | 1 |
| 지시 | 킷 지시문을 보내고 허락 요청을 처리합니다 | 2 · 3 |
| 브라우저 확인 | `index.html`을 열고 새로 고쳐 봅니다 | 4 |
| 수정 | 한 번에 한 가지씩 다시 지시합니다. 망가지면 복사본으로 되돌립니다 | 5 · 6 |

## 1. 요구사항: 지시하기 전에 파일을 확인하기

Claude Code는 파일에 적힌 대로 만듭니다. 지시하기 전에 세 가지를 봅니다.

- [ ] 입력창 아래 폴더 선택이 `personal-brand-site`다
- [ ] `worksheet.md`의 「계층별 슬로건 표」 · 「순서와 시각화 전략표」가 채워져 있고 저장했다
- [ ] 작업 폴더 맨 위에 `index.html`(어제의 뼈대)과 `DESIGN.md`가 있다

이번에 바라는 것을 한 문장으로 말할 수 있어야 합니다. 예) "첫 화면에서 내 이름과 대표 슬로건이 가장 먼저 보이면 좋겠다." 그 문장이 워크시트의 어느 칸에 있는지 짚어 봅니다. 워크시트에 없는 바람이면 먼저 워크시트에 적습니다. 그래야 다음 지시에서도 같은 기준을 씁니다.

## 2. 지시: 킷 지시문 보내기

1. 새 날의 첫 지시라면 새 대화를 엽니다. 새 대화를 시작하는 버튼의 위치는 앱 버전에 따라 다를 수 있습니다. 새 대화에서도 폴더 선택이 맞는지 다시 봅니다.
2. 지시문 킷의 「[첫 화면 지시문](../kits/claude-code-prompts.md)」을 찾아 코드 상자 안의 글을 통째로 복사합니다. 교재의 지시문 상자는 줄인 것이니 늘 킷의 전문을 씁니다.
3. 입력창에 붙여 넣고 보냅니다. 붙여 넣은 글의 줄 바꿈은 그대로 들어갑니다. 직접 줄을 바꿀 때는 `Shift+Enter`를 씁니다. `Enter`만 누르면 바로 보내질 수 있습니다.
4. 끝날 때까지 기다립니다. 중간에 새 지시를 보내지 않습니다.

파일은 `@`로 가리킵니다. 입력창에 `@`를 치면 파일 이름 후보가 뜨므로 골라서 넣으면 오타가 없습니다.

## 3. 허락 요청이 뜰 때

파일을 만들거나 고치기 전에 Claude Code가 허락을 물을 수 있습니다. 묻는 창의 문구와 버튼 이름은 앱 버전과 모드 선택에 따라 다르므로, 버튼 이름보다 **무엇을 허락하는지**를 읽고 누릅니다. 볼 것은 세 가지입니다. **어느 파일인가 · 무엇을 하는가 · 내가 시킨 일인가.**

| 묻는 것 | 이렇게 합니다 |
|---|---|
| `personal-brand-site` 안의 `index.html` · `DESIGN.md` 고치기, 복사본 만들기 | 지시문에 적은 일이면 허락합니다 |
| `worksheet.md` · `resume.md` 고치기 | 사이트 지시문에서는 고칠 일이 없습니다. 거절합니다 |
| 파일 지우기 | 내가 시킨 일인지 한 번 더 봅니다. 시키지 않았으면 거절합니다 |
| 작업 폴더 밖의 파일, 프로그램 설치 | 거절하고 아래 말을 보냅니다. 사이트를 만드는 데는 설치할 것이 없습니다 |
| 명령 실행 (Vercel 배포 등) | 3.3절 배포 때만 허락합니다(「[공개와 배포 가이드](publish-deploy-guide.md)」) |

```text
작업 폴더 밖은 고치지 말고, 프로그램도 설치하지 마. 외부 라이브러리 없이 HTML · CSS · JavaScript로만 해 줘. 왜 그게 필요했는지 먼저 설명해 줘.
```

## 4. 브라우저 확인

1. 처음 한 번은 작업 폴더의 `index.html`을 Chrome 창으로 끌어다 놓거나 두 번 눌러 엽니다(교재 부록 A-3).
2. 그 탭은 닫지 않고 둡니다. Claude Code가 고칠 때마다 그 탭에서 새로 고침(Mac `Cmd+R`, Windows `Ctrl+R`)을 누릅니다. 그래도 바뀌지 않으면 강력 새로 고침(Mac `Cmd+Shift+R`, Windows `Ctrl+Shift+R`)을 누릅니다.
3. 주소창 끝이 `personal-brand-site/index.html`인지 봅니다. 복사본(`index-day1.html` 등)을 열어 놓고 바뀌지 않는다고 헷갈리는 일이 많습니다.

**「첫 화면 지시문」이 끝난 뒤 이렇게 나오면 정상입니다.**

- 작업 폴더에 `index-day1.html`(어제 뼈대의 복사본)이 새로 생겼습니다.
- 브라우저 첫 화면에 이름 · 직함 · 대표 슬로건이 크게 보이고, 사진 자리는 아직 회색 상자입니다.
- 색과 글꼴이 `DESIGN.md`의 규칙을 따릅니다.
- 2번 섹션부터 아래는 어제의 뼈대 그대로입니다.
- Claude Code가 바꾼 곳을 짧게 알려 줍니다.

**휴대폰 화면도 한 번 봅니다.** Chrome 개발자 도구(Mac `Cmd+Option+I`, Windows `F12`)를 열고 왼쪽 위 휴대폰 모양의 기기 화면 아이콘을 누릅니다. 이름과 대표 슬로건이 첫눈에 보이는지 봅니다. 자세한 점검은 「[움직임 넣기 가이드](motion-guide.md)」 6번을 봅니다.

## 5. 수정: 한 번에 한 가지씩

브라우저에서 마음에 들지 않는 곳을 하나만 고릅니다. 고칠 곳을 말할 때는 세 가지를 넣습니다.

1. **어디를** — 섹션 번호나 섹션 이름, 그 안의 요소(예: "1번 섹션의 대표 슬로건")
2. **어떻게** — 크기 · 위치 · 색 · 순서처럼 눈으로 확인할 수 있는 말로
3. **나머지는 그대로** — "다른 곳은 고치지 마"

| 이렇게 말하기보다 | 이렇게 지시합니다 |
|---|---|
| 더 멋지게 해 줘 | 1번 섹션의 대표 슬로건 글자를 지금보다 한 단계 크게, 줄 간격은 넓게 해 줘. 다른 곳은 고치지 마. |
| 휴대폰에서 이상해 | 휴대폰 화면(가로 390px)에서 1번 섹션의 이름이 두 줄로 깨져. 휴대폰에서만 글자를 줄여 한 줄로 보이게 해 줘. 다른 곳은 고치지 마. |
| 색이 별로야 | 1번 섹션의 배경색만 @DESIGN.md 의 주색으로 바꿔 줘. 글자색은 배경과 잘 구분되게 맞춰 줘. 다른 곳은 고치지 마. |
| 순서가 이상해 | 2번 섹션과 3번 섹션의 순서를 바꿔 줘. 문장은 그대로 둬. 그다음 @worksheet.md 의 「순서와 시각화 전략표」에서 바뀐 순서를 내가 직접 고칠게. |

### 다시 지시하는 말

| 이렇게 나왔다 | 다시 지시하는 말 |
|---|---|
| 첫 화면만이 아니라 다른 섹션도 바뀌었다 | 1번 섹션 말고 바뀐 곳을 모두 목록으로 알려 줘. 그 부분은 @index-day1.html 과 똑같이 되돌려 줘. |
| 워크시트에 없는 경력 · 숫자 · 문장이 들어갔다 | index.html 에서 @worksheet.md 와 @resume.md 에 없는 내용을 모두 찾아 보여 주고, 그 부분을 지워 줘. 다른 곳은 고치지 마. |
| DESIGN.md의 색과 다르다 | @DESIGN.md 에서 읽은 색 · 글꼴 규칙을 먼저 목록으로 보여 줘. 그다음 1번 섹션이 그 규칙과 다른 곳만 고쳐 줘. |
| 무엇을 바꿨는지 모르겠다 | 방금 바꾼 곳을 바뀌기 전 · 바뀐 뒤로 나란히 짧게 보여 줘. 파일은 고치지 마. |
| 고쳐 달라고 해도 계속 어긋난다 | 무엇을 바꿀지 목록으로 먼저 보여 주고, 내가 좋다고 하면 고쳐 줘. |
| 사진 자리에 아무 사진이나 넣었다 | 사진 자리는 회색 상자로 되돌려 줘. 사진은 2.4절에서 내가 고른 파일로 넣을 거야. |

## 6. 되돌리기: 큰 변경 전에 복사본 남기기

룩앤필처럼 화면 전체가 바뀌는 지시 전에는 복사본을 남깁니다(교재 2.2절). 킷의 「첫 화면 지시문」은 `index-day1.html`을, 「룩앤필 지시문」은 `index-before-lookfeel.html`을 스스로 남깁니다. 그 밖의 큰 변경 전에는 이름을 `index-before-<다음 작업>.html` 한 가지 형식으로 씁니다. `<다음 작업>`은 영문 소문자와 하이픈으로 짧게 씁니다. 예) `index-before-projects.html`

```text
지금 index.html 을 index-before-projects.html 로 복사해 둬. 복사본은 고치지 마. 복사가 끝나면 다음 지시를 기다려 줘.
```

결과가 망가졌으면 이렇게 되돌립니다.

```text
index.html 을 index-before-projects.html 과 똑같은 내용으로 되돌려 줘. 복사본 파일은 그대로 둬.
```

- 직접 되돌릴 때는 망가진 `index.html`을 지우고, 복사본을 한 번 더 복사해 이름을 `index.html`로 바꿉니다. 복사는 Mac Finder에서 `Cmd+D`(복제), Windows 파일 탐색기에서 `Ctrl+C` → `Ctrl+V`입니다. 복사본 자체는 늘 남겨 둡니다.
- 이미 저장소에 올린 파일은 저장소에서 그 파일을 열고 **History**를 누르면 올렸을 때의 내용을 볼 수 있습니다.

## 7. 대화가 무거워지면 새 대화로 옮기기

아래 신호가 보이면 그 대화는 더 쓰지 않습니다.

- 같은 말을 되풀이한다
- 앞에서 "고치지 마"라고 한 곳을 또 고친다
- 이유 없이 작업을 거절하거나, 답이 중간에 끊긴다

사이트는 모두 파일에 남아 있으므로 새 대화로 옮겨도 잃는 것이 없습니다. 새 대화를 열고 이렇게 시작합니다.

```text
@index.html 은 내 개인 브랜드 사이트야. @worksheet.md 의 「순서와 시각화 전략표」와 @DESIGN.md 를 읽고, 지금 사이트의 섹션 목록과 섹션마다 다 된 것 · 아직 안 된 것을 짧게 알려 줘. 파일은 아직 고치지 마.
```

목록이 맞으면 하던 지시를 이어서 보냅니다. 대화를 요약해 붙이지 않습니다. 새 대화에 넘기는 것은 파일뿐입니다.

## 다른 AI 코딩 도구를 쓸 때

지시문은 그대로 쓰고, `@` 파일 지정과 허락 방식만 그 도구에 맞춥니다. 자세한 대응은 「[다른 AI 코딩 도구로 할 때 (OpenAI Codex · Cursor)](../help/other-coding-tools.md)」를 봅니다.

## 자주 하는 실수와 고친 예

- **한 번에 다섯 가지를 고쳐 달라고 했다** — "글자 키우고, 색 바꾸고, 사진 넣고, 버튼 추가하고, 순서도 바꿔 줘." 다섯 곳이 한꺼번에 바뀌어 무엇이 마음에 들지 않는지 알 수 없었습니다. → 복사본으로 되돌리고, 한 가지씩 보내며 그때마다 새로 고쳐 봅니다.
- **말로만 설명했다** — "따뜻한 느낌의 첫 화면"이라고만 보내 내 의도와 다른 색이 나왔습니다. → "`@worksheet.md`의 「순서와 시각화 전략표」 1번 섹션의 '인상'과 `@DESIGN.md`의 색대로"처럼 파일을 가리킵니다.
- **새로 고침을 하지 않고 "안 바뀌었다"고 했다** → 브라우저에서 새로 고침을 누르고, 주소창 끝이 `index.html`인지 봅니다.
- **빠른 응답용 모델로 바꿨다** — 답은 빨라졌지만 고치지 말라는 곳까지 바뀌었습니다. → 입력창 아래 줄 오른쪽의 모델 선택을 처음 쓰던 기본 모델로 되돌리고 다시 보냅니다.
- **Claude Code가 지어낸 수상 경력을 그대로 두었다** — 뼈대를 꾸미며 "업계 최고 수준" 같은 문장과 없는 숫자가 들어갔습니다. → 5번 표의 "워크시트에 없는 내용" 말로 찾아 지웁니다. 공개 전에 3.3절에서 한 번 더 확인합니다.

## 완료 기준 체크리스트 확인 방법

워크시트 「사이트 첫 화면」 끝의 **완료 기준 체크리스트**를 이렇게 확인하고 `- [ ]`를 `- [x]`로 바꿉니다.

- **첫 화면에 이름 · 직함 · 대표 슬로건이 한눈에 보인다** — 브라우저를 열자마자 스크롤하지 않고 세 가지가 보이는지, 휴대폰 화면 보기에서도 그런지 봅니다. 짝에게 3초만 보여 주고 이름과 대표 슬로건을 말할 수 있는지 물어봐도 됩니다.
- **고칠 때마다 한 가지씩만 지시했다** — 대화를 위로 올려 보며, 한 번의 지시에 "그리고"로 여러 일을 묶은 곳이 없는지 봅니다.

## 막혔을 때

- **`@`로 가리킨 파일을 못 찾는다고 합니다.** 다른 폴더를 열었을 가능성이 큽니다. 입력창 아래 폴더 선택이 `personal-brand-site`인지 보고, "이 폴더에 무엇이 있는지 알려 줘"로 확인합니다.
- **브라우저 화면이 하얗게 나옵니다.** "브라우저로 열면 화면이 비어 있어. 원인을 찾아 쉬운 말로 설명하고, 그 부분만 고쳐 줘."라고 보냅니다. 두 번 해도 안 되면 복사본으로 되돌립니다.
- **더블클릭하면 브라우저가 아니라 다른 앱이 열립니다.** 파일을 오른쪽 클릭하고 Mac은 다음으로 열기, Windows는 연결 프로그램에서 Chrome을 고릅니다. 또는 파일을 Chrome 창 위로 끌어다 놓습니다.
- **고쳤다는데 화면이 그대로입니다.** 강력 새로 고침(Mac `Cmd+Shift+R`, Windows `Ctrl+Shift+R`)을 하고, 주소창 끝이 `index.html`인지 봅니다.
- **작업 폴더 밖 파일을 고치거나 무엇을 설치하겠다고 합니다.** 허락하지 않고 3번의 말을 보냅니다.
- **사용 한도에 걸렸습니다.** 만든 파일은 작업 폴더에 그대로 남습니다. 다시 쓸 수 있을 때까지 워크시트 채우기와 사진 모으기(2.4절)를 먼저 합니다. 기다릴 수 없으면 「[다른 AI 코딩 도구로 할 때 (OpenAI Codex · Cursor)](../help/other-coding-tools.md)」를 봅니다.
