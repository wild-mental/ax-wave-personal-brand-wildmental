# 온라인 자료 작성 규칙

인쇄본 교재(2026-11-22 조판본, 컬러판 · 흑백판 55쪽, 두 판의 쪽 번호 같음)와 같은 규칙입니다. 상위 프로젝트 `docs/4-3/TEXTBOOK_SPEC.md`(§5 예제 체계 · §7 구현 실습 · §8 공개 배포 · §9 콘텐츠 발행 · §10 문체 · 표기 · §13 온라인 자료실)에서 온라인 자료에 해당하는 것만 옮기고, 4-2 자료실(`wild-mental/ax-wave-design-thinking-wildmental`)의 `_context/RULES.md`에서 같은 방식을 이어받았습니다.

> 이 저장소는 GitHub Pages로 **공개**됩니다. `_context/`는 사이트에는 안 보이지만 저장소에서는 누구나 볼 수 있습니다. 강사용 내용(피드백 운영, 차시 운영 시간, 설계 의도, 제작 이력)은 여기에도 넣지 않습니다. 그런 내용은 상위 프로젝트의 비공개 문서에만 둡니다.

## 1. 쓰는 말

1. 학생에게 하는 말만 씁니다. 독자는 "여러분", 문체는 합니다체. 안내형("~합니다", "~하세요"). 독자는 처음 배우는 비전공 학생이며, 앞에서부터 읽어도 막히지 않게 씁니다. 학생을 부르는 다른 말(§8 점검 명령에 걸리는 말)은 쓰지 않습니다.
2. 설계 의도("이 수업은 ~하려고"), 피드백 기준과 운영, 차시별 운영 시간, 강사에게 하는 말은 쓰지 않습니다.
3. 전문용어는 처음 나올 때 `원어(우리말: 한 줄 풀이)`. 교재 부록 B 「용어 풀이」와 같은 풀이를 씁니다. CTA는 페이지마다 첫 등장에서 `CTA(Call To Action, 행동 유도: …)`로 씁니다.
4. 예제를 인용할 때는 "중심 예제 백유림"이라고 쓰고, 처음 나오는 곳에서 가상 인물이라고 밝힙니다.

## 2. 정답처럼 보이는 것을 싣지 않기

- 학생은 각자 자기 이력으로 실습합니다. 특정 사람의 "모범 답"이나 완성 산출물을 정답처럼 싣지 않습니다.
- 중심 예제는 교재가 이미 보여 준 것과 텍스트 이력서 작성 예(`worksheet-template/baek-yurim-resume.md`)만 씁니다. 중심 예제는 본보기이지 정답이 아니라고 함께 적습니다.
- "실수 → 고친 예"는 중심 예제 밖(카페 아르바이트, 동아리 회계, 동네 가게 홍보 같은 일반 사례)에서 가져옵니다.
- 피드백은 워크시트 산출물 끝의 **완료 기준 체크리스트**까지만 싣습니다. 그 밖의 피드백 기준과 주는 법은 싣지 않습니다.

### 첫 화면 = 교재 매칭표

`README.md`가 학생이 보는 교재↔자료실 매칭표입니다. 가이드 표의 열은 「교재 절 · 교재 쪽 · 온라인 가이드 · 함께 쓰는 자료」입니다. 교재 쪽은 그 절의 제목이 인쇄된 쪽(절 시작 쪽)입니다. `→ 온라인 가이드` 표시가 인쇄된 쪽은 `_context/TEXTBOOK_HUB_MAP.md`와 `guides.json`의 `mark`에 둡니다. 가이드가 없는 절도 한 줄씩 두고 「온라인 가이드」 칸에 "—"를 씁니다. 가이드 · 자료 · 지시문을 더하거나 교재 쪽이 바뀌면 `README.md`와 강사용 상태 추적표 `_context/TEXTBOOK_HUB_MAP.md`, `_context/guides.json`을 함께 고칩니다.

### 도움말 페이지와 고침 이력

- `help/`의 도움말 3개(「막혔을 때 모음」 · 「다른 AI 코딩 도구로 할 때 (OpenAI Codex · Cursor)」 · 「Windows 사용자 메모」)는 가이드 내용을 모아 가리키는 페이지입니다. 기준은 가이드이므로, 가이드의 막혔을 때 · 다시 지시하는 말 · Mac/Windows 차이를 고치면 해당 도움말도 함께 고칩니다.
- 학생에게 보이는 가이드 · 자료를 고치면 `README.md` 맨 아래 「가이드 고침 이력」에 날짜와 한 줄을 더합니다(오탈자만 고친 것은 빼도 됩니다).

## 5. 코드 이름 금지

버전 기호(영문 V와 숫자), 차시 기호(숫자와 H), 결정 번호(T와 숫자), 옛 산출물 번호(W와 숫자)를 쓰지 않습니다. 풀네임과 지시문 이름만 씁니다.

## 6. 한 곳 원칙

교재에 있는 칸 설명 · 예제 · 지시문 전문은 가이드에서 되풀이하지 않고 "교재 1.5절의 표"처럼 가리킵니다. 지시문 전문은 지시문 킷 한 곳에만 둡니다(가이드의 "다시 지시하는 말"과 사전 안내의 Vercel 준비 지시문은 킷에 없는 보조 문장이라 예외). 가이드는 교재에 없는 것(화면 위치, 이렇게 나오면 정상, 실수와 고친 예, 완료 기준 체크리스트 확인 방법, 다시 지시하는 말, 막혔을 때)을 채웁니다.

## 7. 형식

- 표준 마크다운(GitHub 표 · 체크리스트 포함). HTML은 쓰지 않습니다.
- 이미지는 `guides/images/<가이드 파일 이름>-<번호>.png`에 두고 `![설명](images/…)`로 연결합니다.
- 화면 녹화(동영상 · GIF)는 자료실에 싣지 않습니다.
- 캡처는 꼭 필요한 곳에만 둡니다: 아이콘만 있거나 메뉴 속에 숨어 글로 찾기 어려운 버튼 · 선택. AI가 만든 결과 화면, 폴더 창, 답변 화면, 글자로 이름이 적힌 버튼은 찍지 않고 글로 씁니다. 지금 캡처는 1곳(「작업 폴더와 비공개 저장소 준비 가이드」의 Claude Code 입력창 아래 줄)입니다.

가이드를 고친 뒤 저장소 맨 위에서 실행합니다. 두 번째 명령은 아무것도 나오지 않아야 합니다.

```
python3 -I _context/check-hub.py
grep -rnE '학[습]자|강사[ ]가이드|SaaS[형]|방[문]자|윤[가]온|관[통] 예제|프로필[ ]페이지|브랜딩[ ]페이지|증[거]|\bW[1-6]\b|\b[vV][0-9]\b|\b[1-8]H\b|\bT[0-9]+\b|AOS|DOS|용어집|<[a-z]' README.md pre-course-notice.md guides help worksheet-template/README.md
```

`check-hub.py`는 ① 인쇄본의 가이드 이름마다 제목(`#` 줄)이 같은 가이드 파일이 정확히 하나인지(원고의 `→ 온라인 가이드` 표시 자리 수와 `guides.json`의 자리 수도 대조), ② README · 사전 안내 · 가이드 · 도움말의 상대 링크가 모두 있는 파일을 가리키는지, ③ 금지어가 저장소 어디에도 없는지, ④ 워크시트 원본 · 텍스트 이력서 양식 · 백유림 작성 예 · 지시문 킷이 상위 프로젝트 원본과 같은지 확인합니다(①④는 상위 프로젝트가 옆에 있을 때 원고와 대조).
